SAP 系统集成 APIv1.4

由 SAP Integration Suite（CPI）统一暴露的集成层 REST 接口。前端只用一套 JSON 契约与一套鉴权，背后编排 S/4HANA、MDG、MES、PLM、SRM 等十余个后端系统——协议转换、字段映射、异常重试与链路追踪全部收敛在集成层，让接入方在 15 分钟内完成第一笔成功调用。

API 概览

本套接口是集成层（CPI）对外的门面 API（Facade API）。调用方只面对统一的 REST/JSON 契约；集成层负责把它翻译成后端系统的原生协议——S/4HANA 走 OData V2（A2X），MDG 走 DRF/OData，MES 走 IDoc 或 REST，PLM 走 REST/JSON，SRM/Ariba 走 cXML。

统一契约

所有端点共用一套响应信封：data / paging / meta，错误统一为 error.code 机器可读码。

端到端安全

OAuth 2.0 Client Credentials 换取 Bearer Token；写操作叠加 X-CSRF-Token 与 If-Match 并发控制。

可观测

每次调用返回 meta.correlationId，可直接在 CPI Message Processing Log 中定位到报文与后端往返耗时。

集成架构

通用约定

  • 传输：强制 HTTPS（TLS 1.2+），明文 HTTP 请求会被拒绝并返回 403。
  • 编码：Content-Type: application/json;charset=utf-8，所有响应均为 UTF-8。
  • 时间：ISO 8601，UTC，精度到秒，例如 2026-09-03T02:41:07Z；日期字段使用 YYYY-MM-DD。
  • 金额：字符串形式的十进制数字（"126800.00"），避免浮点误差；币种单独用 currency 字段给出（ISO 4217）。
  • 数量：字符串三位小数，与 SAP 内部精度一致，例如 "500.000"。
  • 编号：业务主键（如销售订单号）一律字符串返回，不做数字类型隐式转换。
  • 分页：page + pageSize，默认 page=1、pageSize=50，最大 200。
  • 追踪：请求可携带 X-Correlation-ID；未携带时由集成层生成，并回显在响应头与 meta.correlationId。
本页所有示例均可直接复制运行。把 $CPI_TOKEN 换成你换取的访问令牌、把 <tenant-host> 换成你的 CPI 运行期主机名即可。写操作还需要先取一次 X-CSRF-Token，详见鉴权与基础 URL。

鉴权与基础 URL

集成层使用 OAuth 2.0 Client Credentials 授权模式：用 client_id / client_secret 向令牌端点换取短期访问令牌，再以 Bearer Token 调用业务端点。令牌有效期 3600 秒，过期返回 401 AUTH_TOKEN_EXPIRED。

基础 URL

PROD https://<tenant-host>.hana.ondemand.com/http/v1
TEST https://<tenant-host>-test.hana.ondemand.com/http/v1

所有端点路径都基于该前缀拼接。例如查询订单列表的完整地址为 https://<tenant-host>.hana.ondemand.com/http/v1/orders。租户主机名由集成团队在开通时下发，形如 acme-cpi-prod.it-cpi01-rt.cfapps.cn40。

第一步 · 获取访问令牌

Shell · 换取 Bearer Token
curl -X POST "https://acme-cpi-prod.authentication.cn40.hana.ondemand.com/oauth/token" \
  -u "$CPI_CLIENT_ID:$CPI_CLIENT_SECRET" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "grant_type=client_credentials" \
  -d "scope=cpi.orders.read cpi.orders.write"

# 建议缓存令牌，过期前 60 秒主动刷新，不要每次调用都换令牌
200 OK · application/json
{
  "access_token": "eyJhbGciOiJSUzI1NiIsImtpZCI6Ijdm...",
  "token_type": "Bearer",
  "expires_in": 3600,
  "scope": "cpi.orders.read cpi.orders.write"
}

第二步 · 获取 CSRF Token（仅写操作）

对 POST / PATCH / DELETE，集成层要求携带 X-CSRF-Token。先以 Fetch 取值，令牌在同一会话内可复用（默认 30 分钟），随响应头一并回传 Set-Cookie / x-csrf-token，请连同 Cookie 一起回传。

Shell · 抓取 CSRF Token
CSRF=$(curl -s -X GET "https://acme-cpi-prod.it-cpi01-rt.cfapps.cn40.hana.ondemand.com/http/v1/orders?pageSize=1" \
  -H "Authorization: Bearer $CPI_TOKEN" \
  -H "X-CSRF-Token: Fetch" \
  -c cookiejar.txt -D - -o /dev/null | grep -i '^x-csrf-token' | awk '{print $2}' | tr -d '\r')

echo "$CSRF"

公共请求头

请求头示例值必填说明
AuthorizationBearer eyJhbGci…必填访问令牌。缺失或过期返回 401。
X-CSRF-TokenRkZSM…==写操作POST / PATCH / DELETE 必填；缺失返回 403 CSRF_TOKEN_MISSING。
Content-Typeapplication/json;charset=utf-8写操作其余类型返回 415 UNSUPPORTED_MEDIA_TYPE。

严禁在浏览器端或公开仓库中暴露 client_secret 与访问令牌。令牌只应在服务端使用；若疑似泄露，立即在租户控制台轮换密钥，旧令牌将在 5 分钟内失效。

GET查询订单列表

GET /http/v1/orders

分页返回授权范围内的销售订单摘要。后端路由至 S/4HANA API_SALES_ORDER_SRV，并按需合并 MDG 主数据治理状态。默认按 updatedAt 倒序；单页最多 200 条。

查询参数 Query

参数类型必填说明
statusstring可选按状态过滤，可逗号分隔多值：draft、submitted、confirmed、partially_delivered、delivered、invoiced、cancelled。
soldToPartystring可选售达方客户编码（SAP 10 位，前导零保留）。
salesOrgstring可选销售组织，如 CN01；不传时按令牌授权范围返回全部。
documentTypestring可选订单类型：OR 标准订单、RE 退货、CR 贷项。
changedSincestring(date-time)可选ISO 8601，返回该时刻之后发生变更的订单，用于增量拉取；与 status 可叠加。
pageinteger可选页码，从 1 开始，默认 1。
pageSizeinteger可选每页条数，1–200，默认 50。
expandstring可选列表页展开子结构：items、pricing、masterData；逗号分隔，默认不展开。

POST创建订单

POST /http/v1/orders

创建一张销售订单。集成层按顺序执行三段编排：① 结构校验 → ② MDG 主数据校验（物料/客户是否已治理通过）→ ③ S/4HANA A2X 过账（含定价与 ATP 可用性检查）。任一步失败则整体回滚，不产生半张订单。

请求体参数 Body

字段类型必填说明
externalIdstring(40)必填调用方业务单号，写入 S/4HANA 采购订单编号字段；同 salesOrg 下唯一，重复返回 409。
documentTypestring必填订单类型：OR / RE / CR。
salesOrgstring(4)必填销售组织。
distributionChannelstring(2)必填分销渠道。
divisionstring(2)必填产品组。
soldToPartystring(10)必填售达方客户编码。
shipToPartystring(10)可选送达方，缺省取 soldToParty。
requestedDeliveryDatestring(date)必填请求交货日期，不得早于当日。
purchaseOrderNumberstring(35)可选客户采购订单号，用于发票与对账。
incotermsstring(3)可选国际贸易条款，如 EXW、FOB、DDP。
paymentTermsstring(4)可选付款条件代码，如 NT30。
itemsarray<object>必填行项目，至少 1 条，最多 200 条。
itemNostring(6)可选行号，形如 000010；缺省按步长 10 自动生成。
materialstring(40)必填物料编码；未通过 MDG 治理的物料返回 422 MDG_VALIDATION_BLOCKED。
quantitystring(decimal)必填数量，三位小数字符串，必须 > 0。
unitstring(3)必填计量单位：EA、KG、M、PC。
plantstring(4)必填工厂；用于 ATP 可用性检查。
storageLocationstring(4)可选库存地点。
netPricestring(decimal)可选手工净价，留空则由 S/4HANA 条件定价自动带出。
textstring(132)可选订单抬头文本，写入 S/4HANA 长文本。
skipAtpCheckboolean可选默认 false；置 true 跳过可用性检查，需令牌具备 cpi.orders.admin 作用域。

PATCH更新订单

PATCH /http/v1/orders/{id}

采用 JSON Merge Patch（RFC 7386） 语义：只传要改的字段，未出现的字段保持不变，显式传 null 表示清空。行项目按 itemNo 定位并声明 action。必须携带 If-Match，防止并发覆盖。

路径与请求头

重试策略建议

  • 仅对 429、500、502、503、504 自动重试；4xx 业务错误重试无意义。
  • 采用指数退避 + 抖动：初始 1 秒，每次 ×2，上限 60 秒，最多 6 次；抖动 ±20% 避免重试风暴。
  • 优先使用响应头 Retry-After 的秒数，它已考虑后端实际排队情况。
  • 写操作务必携带 Idempotency-Key——24 小时内重放返回首次结果，不会重复过账。
  • 批量场景主动降速到配额的 70%，并错开整点（整点常有定时任务争抢配额）。
Pseudocode · 退避重试
delay = 1s
for attempt in 1..6:
  resp = request()
  if resp.status in (429,500,502,503,504):
      wait = resp.header("Retry-After") or delay
      wait = wait * (1 + random(-0.2, 0.2))   # 抖动
      sleep(wait)
      delay = min(delay * 2, 60s)
  else:
      break
